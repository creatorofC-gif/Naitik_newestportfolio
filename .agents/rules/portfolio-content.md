# Portfolio Content Rules

## Source of Truth

The primary portfolio data source is:

src/data/profileData.ts

---

## Never Invent Information

Never invent:

- companies
- clients
- projects
- experience
- job titles
- skills
- years of experience
- statistics
- revenue
- performance metrics
- testimonials
- certifications
- achievements

Only use information provided by the project data.

---

## Missing Information

If information is missing:

Do not fabricate it.

Use:

- existing data
- a clearly marked placeholder
- or leave the field empty

---

## Project Information

Projects should remain structured and data-driven.

A project may contain:

- title
- description
- category
- technology
- impact
- metrics
- architecture
- images
- URLs

Do not duplicate project content inside components.

---

## Professional Positioning

The website should communicate technical depth through:

- architecture
- engineering decisions
- projects
- systems
- technologies
- measurable results when provided

Do not create fake credibility through invented statistics.

---

## Copywriting

Content should be:

- concise
- technically credible
- confident
- professional

Avoid exaggerated marketing language.

Do not describe every feature as:

"revolutionary"

"groundbreaking"

"world-class"

"next-generation"

unless the provided content explicitly supports it.
